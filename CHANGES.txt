0.9.3 (unreleased)
==================
JDK 21 migration - phase A (engineering baseline), phase B (off-heap access moved to
java.lang.foreign under --enable-preview), plus a security fix and dependency cleanup.

Build / platform:
- Compile target raised from Java 8 to Java 21 (source/target = 21).
- Maven plugins upgraded to JDK 21-compatible versions (compiler 3.13.0, surefire 3.2.5,
  javadoc 3.6.3, jar 3.4.1, source 3.3.0, gpg 3.2.4, felix bundle 5.1.9, and others).
- Added `.mvn/jvm.config` to force UTF-8 output (fixes non-ASCII compiler messages on
  Windows zh_CN systems).
- Added `--add-exports java.base/sun.nio.ch=ALL-UNNAMED` at compile time for the chunked
  implementation's use of `sun.nio.ch.DirectBuffer` (transitional, to be removed in 1.0).

Code simplification:
- Removed `org.caffinitas.ohc.util.ByteBufferCompat` (ASM-generated ByteBuffer bridge class),
  which was only needed to bridge ByteBuffer method-signature changes across Java 8/9-11.
  With source 21 the plain ByteBuffer API is used directly.
- Dropped the `org.ow2.asm:asm` dependency (no longer referenced).

Dependencies:
- slf4j 1.7.32 -> 2.0.20 (log4j binding switched to `log4j-slf4j2-impl`).
- log4j 2.16.0 -> 2.26.1.
- testng 7.4.0 -> 7.12.0.
- guava 31.0.1-jre -> 33.8.0-jre.
- jna 5.10.0 -> 5.19.1.
- snappy-java 1.1.8.4 -> 1.1.10.12.
- lz4: migrated from abandoned `net.jpountz.lz4:lz4:1.3.0` to `at.yawk.lz4:lz4-java:1.13.0`
  (package name `net.jpountz.xxhash` preserved, no source changes needed).

JDK 21 off-heap access (FFM, phase B) - requires --enable-preview:
- `sun.misc.Unsafe` direct-memory access and the `sun.nio.ch.DirectBuffer` /
  `Unsafe.allocateInstance` fabricated-DirectByteBuffer hacks are replaced by the Foreign
  Function & Memory API: element read/write via `MemorySegment` (`ValueLayout.*_UNALIGNED`),
  bulk copies via `MemorySegment.copy`, zero-fill via `MemorySegment.fill`, and off-heap
  ByteBuffer views via `MemorySegment.asByteBuffer` (B1a/B1b/B1c).
- The `java.lang.foreign` API is a *preview* feature in JDK 21 (JEP 442; finalized only in
  JDK 22 / JEP 454). Compiling and running therefore require `--enable-preview`
  (and `--enable-native-access=ALL-UNNAMED` to silence restricted-method warnings). The
  resulting bytecode is locked to the JDK 21 feature release and is not normally publishable
  to Maven Central; a clean, preview-free, fully Unsafe-free build targets JDK 22+.
- Remaining `sun.misc.Unsafe` usage: the off-heap atomics used for entry reference counting
  and the sentinel CAS (`getAndAddInt`/`getAndSetLong`), which have no FFM equivalent in the
  JDK 21 preview API (they arrive in JDK 22).

Security:
- Fixed a chunked-implementation off-heap out-of-bounds write (CWE-787) in
  `org.caffinitas.ohc.chunked.OffHeapChunkedMap.putEntry`: an entry whose serialized size
  exceeds a single chunk's data area was copied past the chunk and, for the last chunk, past
  the end of the segment's off-heap allocation, corrupting memory and crashing the JVM.
  `putEntry` now refuses such oversized entries (`put` returns false), mirroring the linked
  implementation's "refuse entries above maxEntrySize" behavior. Reported against this
  project via the MIIT National Vulnerability DB (NVDB/CNVDB); may not be publicly disclosed
  yet. Source analysis indicates the missing bound existed in the chunked path throughout the
  0.x history (not re-verified release-by-release).
- Added regression test `ChunkedOversizedEntryTest` (oversized entries are refused without
  crashing).
- Behavior change: on the chunked implementation, `put`/`addOrReplace`/`putIfAbsent` of an
  entry larger than one chunk now return false instead of risking memory corruption.
- Dependency bumps above also address published advisories: Guava 33.8.0 (deserialization
  uncontrolled-allocation, CVE-2026-102554 / GHSA-xxph-c9ww-hj94) and Log4j2 2.26.1.

Documentation:
- README, BUILDING updated to reflect the Java 21 requirement and current module state.

0.9.0
=====
Forked from org.caffinitas.ohc 0.7.4, with ongoing development targeting the current mainstream and stable Java platform (Java 21).

Notice:
Current version will start from 0.9.x
The current version is a simple replica, without much customized modification.
In the future, more modern changes will be made on this forked branch for on Java 21 edition,
gradually consolidating the API levels of the off-heap cache implementation and removing `unsafe`.
